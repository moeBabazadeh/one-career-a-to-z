A weekend at the end of the month, lots of tokens to spare, and a strange idea: one career, told 26 different ways. So I built my website 26 times.

Every theme on [babazadeh.dev](/) is the whole site. The roles, the products, the hardware and the open-source work are the same in each one, but the page around them is a different working tool. There is one for every letter, from an [API reference](/concepts/api-reference) to a [zoom through the full stack](/concepts/zoom), and the [gallery](/concepts) lists them all.

## Real tools, not mock-ups

The bar for a theme was that it has to work:

- [Pull Request](/concepts/pull-request) is the site as a pull request. You read the diff, watch CI run, leave a review, then merge.
- [Query Plan](/concepts/query-plan) is the career as a database. You write SQL against it and watch `EXPLAIN ANALYZE` stream rows through the plan.
- [Kickoff](/concepts/kickoff) plays a Small Size League match live, and the career reads like a match report.

## One source of facts

Twenty-six designs means twenty-six places for a date or a number to go stale. So every fact lives in one file, `src/content/db.ts`, and every theme reads from it. A lint rule fails the build when a fact is typed straight into a theme:

```js title="eslint.config.mjs" {2,4}
const FACTS = [
  // A month and a year: "Sep 2026", "June 2024".
  String.raw`\b(January|February|…|Nov|Dec) (19|20)\d\d\b`,
  // A lower bound: "200+", "0.5B+", "11.8k+".
  String.raw`\b\d[\d.,]*[kKMB]?\+`,
];
```

Changing a job title or a commit count is now a one-line edit, and all 26 themes pick it up.
